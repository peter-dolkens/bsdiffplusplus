# research/ — "what would make bsdiff 6 better than the 2006 thesis?"

Findings are in [`REPORT.md`](REPORT.md). This file says how to rerun the measurements.

Everything here is throwaway measurement code. Nothing outside `research/` is modified. Corpus
files are only read as data, never executed. Nothing was downloaded (`downloads/` is empty); the
literature in the report was read on the web, not fetched into the tree.

## Layout

```
REPORT.md       generated: tools/build_report.py <- report_src/main.tmpl + results/tables.json
report_src/     the report's prose (main.tmpl, q7.md)
tools/          sources (C and Python, standard library only)
bin/            compiled C tools (rebuild with tools/build.sh)
csalign/        a .NET project that compiles a SNAPSHOT COPY (csalign/src, taken 03:06) of the
                project's Common + Alignment + Matching sources, to obtain its DP alignment
results/        JSON results; tables.json / tables.md are the report's tables
work/           per-pair scratch (patches, alignments, address maps); regenerated by the scripts.
                The large intermediates (maps, per-byte cost files, diff strings) were deleted after
                the tables were built; rerun the steps below to get them back
```

## Build

```sh
sh tools/build.sh                              # clang; system zlib + bzip2, Homebrew liblzma (lzdict)
(cd csalign && dotnet build -c Release)        # only for the DP-alignment tables
```

## Reproduce

Run from `research/`. Every driver runs at most 3 jobs at a time and gives each job a hard time
budget (`--timeout`), because the machine was shared.

| step | command | produces | what the numbers are |
|---|---|---|---|
| bsdiff 4.3 patches | `python3 tools/make_patches.py` | `work/<pair>/b43.patch` | real patches from `bench/baseline/bsdiff43` |
| Q1 decomposition | `python3 tools/q1_decompose.py` | `results/q1.json`, `work/<pair>/{ctrl,diff,extra}.bin`, `segs.bin` | real section sizes; the parser's reconstruction is checked against `new` |
| thesis-format cost | `python3 tools/run_thesis.py b43` (also `greedy`, `dp`, `dpb`) | `results/thesis_<align>.json`, `work/<pair>/t43/` | map = true code length of BWT + uniform midpoint (matches the C# coder to 1 byte on 14 pairs); the rest real zlib/bzip2 streams |
| Q2 codecs | `python3 tools/q2_codecs.py [--fast]` | `results/q2.json` (resumable) | real compressed streams, incl. old-file-as-dictionary |
| conditional coder | `sh tools/chain_main.sh` = `python3 tools/run_cm.py full_va`, `diff`, `diff_id` | `results/cm_<config>_<align>.json` | length of a real arithmetic-coded stream; `cm` decodes it again without access to `new` and fails on any mismatch |
| Q4 oracle | `python3 tools/run_q4.py` | `results/q4_oracle_b43.json`, `work/<pair>/expl_b43.bin` | counts (upper bound, not a size) |
| DP alignment | `python3 tools/run_csalign.py local,both` | `work/<pair>/segs_dp.bin`, `segs_dpb.bin`, `results/csalign.json` | the project's aligner (snapshot) |
| second batch | `sh tools/chain2.sh` | codec gaps, `thesis_dp`, `ctrl.json`, `cm_full_va_dp`, ablations, reduced models, Go bases, per-section table | as above |
| per-section breakdown | `python3 tools/q4_sections.py [pair]` | `results/q4_sections_b43.json` | counts + exact per-section code lengths from `cm -c` |
| Go bases per section | `python3 tools/go_rbase_sections.py` (after `chain2.sh`) | `results/go_rbase_sections.json` | exact per-section code lengths with base-relative offsets |
| branch-convert then bsdiff | `python3 tools/q7_bcj_bsdiff.py --small` | `results/q7_bcj.json` | real bsdiff 4.3 patches of filtered files; filter inverse verified |
| tables, report | `python3 tools/tables.py && python3 tools/build_report.py` | `results/tables.{json,md}`, `REPORT.md` | |

## The tools

- `tools/b43.py` — BSDIFF40 parser: sections and exact alignment (`segs.bin`: `int32 count`, then
  `(newPos, length, oldPos)` int32 triples, `oldPos = -1` for extra).
- `tools/lab.h` — shared C: file/segment I/O, a port of `dev/format-harness/GreedyAligner.cs`,
  int32 qsufsort (from `ref/bsdiff-4.3/bsdiff.c`), the four difference modes, BWT of the map and
  the midpoint code length, DESIGN 7.1/7.2 varints and control string.
- `tools/thesis.c` — cost of the DESIGN §7 encoding for a given alignment.
- `tools/cm.c` + `tools/addr.h` — the conditional context-mixing coder and the address
  hypotheses. `cm old new segs.bin|greedy [-x 0|1] [-a mask] [-v old.vamap new.vamap] [-C] [-K]
  [-d domain] [-T log2size] [-A abl] [-M/-V ctxmask] [-c costfile] [-n] [-o stream]`; the header
  comments list the flags and the hypothesis bitmask. Configurations used in the report are
  named in `tools/run_cm.py` (`CONFIGS`).
- `tools/q4.c` — oracle: which differing bytes are exactly explained by an alignment-mapped
  field; trigger precision; learned-target oracle.
- `tools/vamap.py` — ELF64 / Mach-O 64 / PE32+ header parsing: offset↔VA regions, section list.
- `tools/gobases.py` — base lists for the base-relative offset hypothesis (section starts, or
  Go `pcHeader` sub-tables).
- `tools/lzdict.c` — raw LZMA2 with a preset dictionary (liblzma), round-trip checked.
- `tools/bcj.c` — minimal invertible x86 E8/E9 and ARM64 BL converters.

## Caveats that apply to every timing in the report

Other agents were building and benchmarking on the same machine, and this session's processes
ran at background priority on the efficiency cores. Times are CPU seconds of the process and
are pessimistic. Sizes are unaffected. A first batch of long runs was stopped part-way to free
the machine; nothing from those partial runs is used.
